The IT direction I'm choosing

HZ splits HBO-ICT into two directions after the propedeuse year: Software Engineering and Data Science. Here's what I know of both, and which one I'm picking.

Software Engineering

This direction is about designing and building working software: architecture, clean code, APIs, databases, and increasingly testing and CI/CD so that what you build keeps working after you ship it. It's the direction behind courses like Software Engineering Basics and Web Application Development in my curriculum. I already live a lot of this outside class too - on VroegSignaleren I'm the one writing the backend and wiring it up with Docker, and on my freelance client's business-optimisation tool I design the whole thing myself, from database to UI.

Data Science

Data Science is about turning raw data into something a person or a system can act on: cleaning messy data, finding patterns, building models, and explaining what they actually mean. It shows up in my curriculum as Foundations of Data and Data Science Basics. VroegSignaleren itself is a signalling product built with HZ researchers, so I regularly see the data side of the project even though I'm not the one doing the analysis - I build the software that turns their signals into something usable. That's given me real respect for the field, but analysis and statistics interest me less than shipping a working product does.

My pick: Software Engineering, leaning backend

Fullstack, of course - but if I'm honest, backend is more what I like. On the frontend I lean more on creativity, and that's something I want to fix rather than avoid. Between the two HZ directions, Software Engineering fits how I already work: I enjoy designing a system end to end and owning it, more than I enjoy analysing a dataset someone else collected.

What I already know

  • Docker basics.
  • Python basics.
  • TypeScript.
  • Unit testing - the basics.
  • CI/CD - I understand it and have vibe-coded pipelines, but never set one up from zero.

What I want to get better at

  • Solid fullstack, so the frontend isn't the weak part.
  • Setting up a real CI/CD pipeline from scratch myself.
  • Writing tests as a habit, not an afterthought.
